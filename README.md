# Shell Emulator

Эмулятор командной оболочки UNIX-подобной операционной системы.

Вариант №8.

## Этап 1. REPL

На первом этапе реализован графический прототип эмулятора.

Поддерживается:

- графический интерфейс на Java Swing;
- заголовок окна с именем пользователя и hostname;
- ввод команд в интерактивном режиме;
- раскрытие переменных окружения, например `$HOME`;
- разбор строки на команду и аргументы;
- команды-заглушки `ls` и `cd`;
- команда `exit`;
- сообщения об ошибках для неизвестных команд и неверных аргументов.

## Этап 2. Конфигурация

На втором этапе добавлен запуск эмулятора с параметрами командной строки.

Программа принимает два обязательных аргумента:

1. Путь к JSON-файлу виртуальной файловой системы.
2. Путь к стартовому скрипту.

При запуске программа:

- проверяет количество аргументов;
- проверяет существование файла VFS;
- проверяет существование стартового скрипта;
- выводит полученную конфигурацию в окно;
- читает стартовый скрипт построчно;
- выполняет команды стартового скрипта;
- останавливает выполнение стартового скрипта при первой ошибке.

## Этап 3. Виртуальная файловая система

На третьем этапе реализована загрузка виртуальной файловой системы из JSON.

Вся виртуальная файловая система загружается в оперативную память. Исходный JSON-файл во время работы эмулятора не изменяется и не распаковывается.

Поддерживается:

- загрузка VFS с помощью библиотеки Jackson;
- представление файлов и каталогов объектами Java;
- произвольная глубина вложенности каталогов;
- текстовое содержимое файлов;
- двоичное содержимое файлов в формате Base64;
- проверка структуры виртуальной файловой системы;
- обнаружение некорректного Base64;
- проверка того, что корень VFS является каталогом;
- несколько вариантов VFS для тестирования.

## Этап 4. Команды для работы с VFS

На четвёртом этапе реализованы команды для работы с виртуальной файловой системой.

Поддерживаются команды:

- `ls` — вывод содержимого текущего или указанного каталога;
- `cd` — переход в указанный каталог;
- `date` — вывод текущих даты и времени;
- `du` — вычисление размера файла или каталога;
- `exit` — завершение работы эмулятора.

Команды `ls`, `cd` и `du` работают только с виртуальной файловой системой, загруженной в оперативную память.

Поддерживаются:

- абсолютные пути, например `/home/user`;
- относительные пути, например `docs`;
- `.` — текущий каталог;
- `..` — родительский каталог;
- `/` — корневой каталог VFS.

Команда `du` выводит размер в байтах. Для файла учитывается размер его содержимого, а для каталога рекурсивно складываются размеры всех вложенных файлов.

Обрабатываются ошибки:

- неправильное количество аргументов;
- несуществующий путь;
- попытка выполнить `cd` для файла;
- неизвестная команда.

## Этап 5. Дополнительные команды

На пятом этапе реализованы команды, изменяющие состояние виртуальной файловой системы.

Поддерживаются команды:

- `cp SOURCE DESTINATION` — копирование файла;
- `cp -r SOURCE DESTINATION` — рекурсивное копирование каталога;
- `rm PATH` — удаление файла;
- `rm -r PATH` — рекурсивное удаление каталога;
- `help` — вывод списка команд с описанием их работы.

Команда `cp` поддерживает копирование по абсолютным и относительным путям. Если путь назначения является существующим каталогом, копия получает имя исходного объекта.

При копировании создаётся независимая копия объекта и всего его вложенного содержимого.

Команда `rm` не позволяет удалить:

- корень VFS;
- текущий каталог;
- каталог, внутри которого находится текущий каталог.

Обрабатываются ошибки:

- неправильное количество аргументов;
- неизвестный параметр;
- несуществующий исходный путь;
- копирование каталога без флага `-r`;
- удаление каталога без флага `-r`;
- невозможность создать копию по указанному пути;
- попытка удалить защищённый каталог.

## Формат VFS

Каждый объект виртуальной файловой системы имеет тип:

- `DIRECTORY` — каталог;
- `FILE` — файл.

Каталог содержит объект `children` с дочерними файлами и каталогами:

```json
{
  "type": "DIRECTORY",
  "children": {
    "example.txt": {
      "type": "FILE",
      "encoding": "TEXT",
      "content": "Example text"
    }
  }
}
```

Текстовый файл использует кодировку `TEXT`:

```json
{
  "type": "FILE",
  "encoding": "TEXT",
  "content": "Hello!"
}
```

Двоичный файл использует кодировку `BASE64`:

```json
{
  "type": "FILE",
  "encoding": "BASE64",
  "content": "AAECAwQ="
}
```

## Варианты VFS

В каталоге `vfs` находятся следующие корректные варианты:

- `minimal.json` — пустая виртуальная файловая система;
- `multiple-files.json` — виртуальная файловая система с несколькими файлами;
- `example.json` — файловая система с несколькими уровнями вложенности.

Для проверки обработки ошибок используются:

- `invalid-root.json` — корень VFS является файлом;
- `invalid-base64.json` — файл содержит некорректные данные Base64.

## Стартовые скрипты

Стартовые скрипты находятся в каталоге `startup`.

- `example.txt` — проверка команд `ls`, `cd`, `date`, `du`, `cp`, `rm`, `help`, различных путей, изменения VFS и обработки ошибок;
- `exit.txt` — проверка команды `exit`.

## Требования

- JDK 21;

## Запуск

Запуск выполняется из корня проекта:

```bash
./run.sh vfs/example.json startup/example.txt
```

Первый аргумент задаёт путь к JSON-файлу виртуальной файловой системы.

Второй аргумент задаёт путь к стартовому скрипту.

## Проверка параметров запуска

Скрипты реальной операционной системы находятся в каталоге `tests/scripts`.

Проверка правильных аргументов:

```bash
./tests/scripts/test_valid_arguments.sh
```

Проверка неправильного количества аргументов:

```bash
./tests/scripts/test_argument_count.sh
```

Проверка несуществующих путей:

```bash
./tests/scripts/test_invalid_paths.sh
```

## Проверка вариантов VFS

Проверка минимальной VFS:

```bash
./tests/scripts/test_vfs_minimal.sh
```

Проверка VFS с несколькими файлами:

```bash
./tests/scripts/test_vfs_multiple_files.sh
```

Глубокая структура каталогов содержится в `vfs/example.json` и проверяется при обычном запуске программы.

Каждый скрипт следует запускать из корня проекта.
